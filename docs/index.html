Quick start

  1. Open Hozz and go to the Automatic tab.
  2. Tap Add a destination.
  3. Choose Folder and pick somewhere — iCloud Drive, Dropbox, OneDrive, Google Drive, or a network share.
  4. Tap Send a test. You should see a confirmation immediately.
  5. Save. Grant Health access when asked.

That's it. New Health data now flows to that folder on its own.

Want everything at once? The Export tab writes your entire Health history as a single file. On a well-used phone that is often several million records; the export is resumable and survives being interrupted.

Destinations

Folder

Hozz writes files into any folder the iOS Files app can reach. Whatever already syncs that folder to your computer — iCloud Drive, Dropbox, OneDrive, Google Drive — does the networking.

Why this is usually the best choice:

  • No server to run, no ports to open, no VPN.
  • Works when your computer is switched off — files queue in the cloud.
  • Works away from home.

The trade-off is that your data passes through whichever cloud you picked. If you would rather it never left your own hardware, point the picker at an SMB share on your machine, or use a REST endpoint instead.

REST API

Hozz POSTs each batch to a URL you control. Every request carries these headers: 

Content-Type: application/x-ndjson
Idempotency-Key: <uuid>
Hozz-Batch-Id: <uuid>
Hozz-Batch-Sequence: <n>
Hozz-Record-Count: <n>

If you set an authorization value, it is sent in the Authorization header and stored in your iPhone's Keychain, never in a file or a log.

Retries are safe. If your server commits a batch but the response is lost, Hozz sends the same batch again with the same Idempotency-Key. Store that key and ignore repeats, and you can never end up with duplicates.

How automatic sync really behaves

Every app on iOS lives with the same four constraints. Hozz states them plainly rather than letting you discover them as a mystery.

  • Your iPhone must be unlocked. Apple encrypts the Health database with your passcode. No app can read it while locked. Hozz treats this as "try again shortly", not a failure.
  • iOS decides when Hozz runs. Expect within a few hours of new data, not instantly.
  • Most data types are capped at hourly by HealthKit, no matter what is requested.
  • Force-quitting stops it. If you swipe Hozz away in the app switcher, iOS will not relaunch it until you open it again.

What Hozz guarantees anyway: nothing is ever lost. Hozz remembers exactly where it stopped for every data type, so a missed window is simply sent on the next run. Tools that export "the last hour" cannot make that promise — a skipped window is gone forever, and an overlapping one duplicates.

Data schema

Each NDJSON line is one self-describing record. A quantity sample looks like this:

{
  "schemaVersion": 1,
  "kind": "quantity",
  "id": "6f1b...",
  "type": "HKQuantityTypeIdentifierStepCount",
  "startDate": "2026-01-01T08:00:00.000Z",
  "endDate": "2026-01-01T08:01:00.000Z",
  "quantity": { "unit": "count", "value": 137 },
  "source": { "name": "iPhone", "bundleIdentifier": "com.apple.health" },
  "device": { "name": "iPhone" },
  "metadata": {}
}

Deletions are explicit, so your copy can stay in step with Health:

{ "kind": "deletion", "id": "6f1b...", "type": "HKQuantityTypeIdentifierStepCount", "schemaVersion": 1 }

Dates are ISO 8601 in UTC with fractional seconds. Every record carries a stable id that matches HealthKit's own identifier, which is what makes an insert-or-replace on your side safe.

Running your own receiver

A minimal receiver is about thirty lines. This one keeps a SQLite database and is safe to retry against:

import json, sqlite3
from http.server import BaseHTTPRequestHandler, HTTPServer

db = sqlite3.connect("health.db", check_same_thread=False)
db.execute("CREATE TABLE IF NOT EXISTS samples ("
           "id TEXT PRIMARY KEY, type TEXT, start TEXT, value REAL, raw TEXT)")
db.execute("CREATE TABLE IF NOT EXISTS batches (key TEXT PRIMARY KEY)")

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        key = self.headers.get("Idempotency-Key", "")
        body = self.rfile.read(int(self.headers["Content-Length"]))

        # Seen this batch already? Say OK and change nothing.
        if key and db.execute(
                "SELECT 1 FROM batches WHERE key=?", (key,)).fetchone():
            return self.respond(200)

        for line in body.splitlines():
            if not line.strip():
                continue
            r = json.loads(line)
            if r.get("kind") == "deletion":
                db.execute("DELETE FROM samples WHERE id=?", (r["id"],))
            else:
                db.execute(
                    "INSERT OR REPLACE INTO samples VALUES (?,?,?,?,?)",
                    (r.get("id"), r.get("type"), r.get("startDate"),
                     (r.get("quantity") or {}).get("value"), line.decode()))
        if key:
            db.execute("INSERT OR IGNORE INTO batches VALUES (?)", (key,))
        db.commit()
        self.respond(200)

    def respond(self, code):
        self.send_response(code)
        self.end_headers()

HTTPServer(("0.0.0.0", 8765), Handler).serve_forever()

Run it, point a REST destination at http://your-computer:8765, and tap Send a test.

Shortcuts and Siri

Hozz exposes two actions:

  • Sync Health Data — sends anything new right now.
  • Check Health Sync Status — reports when it last succeeded.

Both work from the Shortcuts app, from Siri, and from a Home Screen or Lock Screen button. Running a sync manually now and then also gives iOS a signal that Hozz is worth scheduling.

Troubleshooting

Nothing has synced in a while

  1. Check you didn't force-quit Hozz. If you did, just open it again.
  2. Make sure Background App Refresh is on for Hozz in iOS Settings.
  3. Turn off Low Power Mode — it suspends background work.
  4. Open the Automatic tab and tap the refresh button to sync immediately.

The test failed

The message shown is the real one from your destination. A folder error usually means it was moved or its cloud account signed out — pick it again. An HTTP error is your server's own status code and body.

A data type shows no records

Apple deliberately does not let an app tell "you denied this" apart from "you have no data here", so Hozz reports it as unknown rather than guessing. Most people have no data for most of the 192 types, so this is normal.

My export file won't open

Exports are standard ZIP archives and open with a double-click on macOS and Windows. If you have an older .ndjson.gz from an early build, use gunzip or Keka.
